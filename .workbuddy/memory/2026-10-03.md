### 关键实现
1. **`noCompress += listOf("onnx","bin","data","refbin")`** —— 前提条件。
   模型必须 STORED，否则 `AssetManager.openFd()` 拿不到真实长度，
   就没法做「大小一致即跳过」的幂等校验。
2. **幂等导入**：`dst.length() == assetSizeOf()` 才跳过；
   catch 分支必须 `delete()` 半截文件，否则下次被误当"已存在"而永久损坏。
3. **Gradle 多 assets 源**：`sourceSets["main"].assets.srcDir(".../model_assets")`，
   `-PbundleModels=true` 切全量/轻量。
4. **硬链接汇总**：`tools/stage_model_assets.py` 用 `os.link()`，同卷零额外占用。

### ⚠️⚠️ 两个重要教训

**1. Git 只追加不删除 —— 提交错了只能重建仓库**
第一版 commit 把 551 个 tools 一次性脚本 + 交付样音都提交了，
`.git` 涨到 **1.8 GB**。第二个 commit 只"删除"文件，但这些对象**永久留在历史里**，
`.git` 依然是 1.8 GB。
→ **解法：`rm -rf .git && git init` 重建**，只提交干净的 74 个文件。
结果 `.git` = **3.0 MB**。**判据：`du -sh .git` 才是仓库真实体积，`git ls-files` 不算。**

**2. `.gitignore` 通配规则必须「限定路径」**
写了裸的 `*.png` → 把 App 图标 `ic_launcher.png` / `atri_avatar.png` **全吞了**
（mipmap/drawable 下全是 png）。同理 `*.bin` 会吞索引文件。
→ **一律写 `/tools/**/*.png`、`/AtriVC/deliverables*/` 这种带路径的规则**，
并用 `!/AtriVC/app/src/main/res/**` 做例外放行。

**3. `git rm --cached` 在 HEAD 跟踪状态下会被后续 `git add -A` 撤销**
必须先 `git reset --hard HEAD` 让索引与 HEAD 一致，删除才被正确记录。
另外 `git add -u` 会**把 HEAD 里已跟踪但该删的文件又带回来**。

**4. Windows 下 `git add` 行为诡异**：`git add tools/stage_model_assets.py`
在有 `tools/*.py` 规则时静默 no-op（被忽略的路径不报错只跳过）。
