**判移植对错的方法论**（不要用绝对相等）：先测 PC 自身的种子噪声本底
（`AR_SEED=11/12/13` → cos 0.9600/0.9208/0.9489），再看端侧 vs PC（cos 0.9171）
→ 差距 1.27~1.46 倍，落在噪声范围内 → 移植正确。工具 `tools/gsv_device_compare2.py`。

### 真机修的 5 个 bug

1. `OnnxJavaType` 未 import（在 `ai.onnxruntime` 包下）
2. **AR 循环越界**：EOS 停止时 `ySeq.removeAt` 已丢最后一步，事后 `ySeq[yLen+i]` 必越界
   → 改用 `semList` 单独收集
3. **日文参考 phone 为空**（端侧只做中文 G2P）→ 离线预计算 `gsv_export_refphones.py`

5. **采样器算子顺序**（最隐蔽）：官方 `rep_pen → top_p(logit空间) → /temp → top_k(pivot 保留 >=) → softmax`
   → 逐行照抄后 AR 步数 95 → 84。`tools/gsv_sampler_check.py` 校验概率 max_abs ≤ 4e-8

### ORT Java 端侧 API 踩坑

1. `Result.get(i).value` 返回类型**看 shape**：含 `?` → `OnnxTensor`；全静态 → **裸数组**，
   必须写 `asF`/`asShape` 两种都兜住。
2. **`attn_mask` 是 bool 张量**，且是 `boolean[][][][]`；构造要 `OnnxTensor.createTensor(env, ByteBuffer, shape, OnnxJavaType.BOOL)`。
3. **encoder → prefill 要原样直传**（`toTensor`），不能转 float。
4. **BERT 输出已是展开后的 `[S,1024]`**（word2ph 的 repeat_interleave 在图内），
   `S = sum(word2ph) = len(phones)`，**不要**再按 `[1,refSeqLen,1024]` 重声明。
5. **日文参考走全零 BERT**（官方 `get_bert_inf()`），端侧不需要真跑 bert，铺零即可。
6. **`refbin` 必须带版本号**，否则改了格式老文件不会被覆盖。
7. **`C:\...\ATRI语音模型` 有中文**，faiss/部分库打不开 → 用 `D:/tmp_atri/`。
8. **`clean_text("zh")` 需要 cwd = GPT-SoVITS 根目录**（找 G2PW 模型），否则 `FileNotFoundError`。

## ✅ UI 合成「失败/闪退」三条真因（已修 + 真机验证）

用户报「合成时总是显示合成失败或者闪退」。**不是 OOM**（15.6GB 内存、可用 4.3GB、`largeHeap=true`），
真因三条，全部已修并真机复验：

1. **没有进度回调** → 进度条卡在 30% 约 45~80 秒，和「卡死/闪退」肉眼无法区分。
   → `runSynthesis` 传 `onStep`，进度按 `0.3 + 0.6*(1-e^(-step/60))` 渐进到 90%，
   文案显示「推理中（AR 第 N 步，X 秒）…」；另外每 10 步打一条 logcat
   （`tts> AR 第 N 步，已用 X 秒`），UI 看不到时也能确认「活着在跑」。
   真机实测：起 → 每 10 步约 4 秒 → 87 步 / 45 秒完成。
2. **语言选择器是空操作** → `ttsLang` 存了但从不传给引擎，而端侧 G2P **只支持中文**。
   选英文/日文再输非中文 → G2P 返回空 → 「合成失败」。
   → 只启用 `zh`，其它 chip 置灰标「（端侧未支持）」并加提示文案。
3. **G2P 报错不可执行** → 改成区分「一个汉字都没有」与「生僻字」两类，
   并给可操作建议。失败提示也带上异常类名（`$kind`），
   便于区分 G2P 空 / ONNX 形状不匹配 / OOM。

补充修的一个真 bug：AR 循环 EOS 停止时 `ySeq.removeAt` 已丢最后一步，
事后 `ySeq[yLen+i]` 越界 → 改用 `semList` 单独收集。

## ✅ QQ 语音代发：从「自动检测」改成「先播再按」（重要结论）

用户明确：**不做实时通话**；流程 = 先合成 → 打开开关 → 按住 QQ 录音 → 自动把音频播出去让 QQ 麦录到。

### 实测结论：这版 QQ 检测不到录音态（花了一整轮才确认）

- 无障碍服务能读 QQ 界面（`uiautomator dump` 拿到 30 条文本），进聊天会话也确实收到事件。
- 但**按下录音键后，无障碍树零变化**：既没有新文本（「松开 发送」「手指上滑」全都没有），
  也没有新窗口（`dumpsys window windows` 前后一致）。录音面板是自绘 View，不进无障碍树。
- 另一个陷阱：**「按住说话」在按下之前就存在**（切到语音输入模式即出现）。
  拿它当判据会在用户还没按的时候就播出去 → 分成 `RECORD_HINTS`（按下才出现，可触发）
  与 `IDLE_HINTS`（仅日志）。
- 事件驱动也不可靠 → 改成**轮询 `rootInActiveWindow`**（QQ 前台 400ms，否则 3s）。

### 最终方案：循环外放 N 秒（默认 20s）

点「开始代发」→ 立刻切 QQ → 按住说话 → 录进去的就是这段 → 松手发送。
循环覆盖「按住多久」这个不确定量；20 秒后自动停。
`QqWatchService` 保留（将来 QQ 版本若暴露录音态就能全自动）。

真机验证：
- 音量自动拉满 2 → 30/30（`STREAM_MUSIC`）；用 `USAGE_MEDIA`（**不要**
  `USAGE_VOICE_COMMUNICATION`，否则再走一遍通话降噪，衰减更狠）。
- 第一轮 22:49:20 开始 → 22:49:40 自动停（正好 20 秒）；第二轮 22:49:44 → 22:49:48 手动停。

## 续：QQ 语音代发改用「蓝牙耳机当虚拟麦克风」（真机验证通过）

### 用户诉求（本轮）

> 合成不闪退了；但连 QQ 语音还有问题；而且**能否不用扬声器**，
> 而是监听 QQ 语音，一启动就把合成/转换好的音频插进去，播一次，然后自动结束 QQ 录音。

追问后用户给了两条**决定性约束**：
1. **「我需要确保这个音频…在不同设备上依旧可以使用（我将会给它开源）」**
2. 「蓝牙耳机已配对」

→ 第 1 条直接**否掉了 root / LSPosed / Magisk / Shizuku** 一切设备相关方案。

### 结论：三件事里两件做不到，用耳机声学回环绕过

| 诉求 | 非 root | 说明 |
|---|---|---|
| ① 不用手机扬声器 | ✅ | 走蓝牙耳机 |
| ② 把音频「插进」QQ 麦克风 | ⚠️ 能但不是 API 注入 | 声学回环 |
| ③ 播完自动结束 QQ 录音 | ❌ | 需 `INJECT_EVENTS`（signature） |
| ④ 自动检测 QQ 录音态 | ❌ | 自绘 View，不进无障碍树 |

### 采用的方案

```
手机 ──A2DP/SCO──▶ 蓝牙耳机喇叭 ──空气──▶ 蓝牙耳机麦 ──SCO──▶ QQ
```

关键：语音/录音模式下 Android 输入路由自动优先选
`AUDIO_DEVICE_IN_BLUETOOTH_SCO_HEADSET`，QQ 录音时拿到的就是耳机麦。

**⚠️ 推翻了上一轮的结论**：上一轮写「用 `USAGE_MEDIA`，**不要** `USAGE_VOICE_COMMUNICATION`」。
本轮**反过来了** —— 刻意用 `USAGE_VOICE_COMMUNICATION`，因为要的就是让系统按
「通话音频」把声音路由到耳机 SCO，与录音端同一条链路。耳机模式下 AEC 本来
就不该生效（AEC 是为「扬声器→麦克风」设计的），所以不再需要躲 AEC。

1. **`AudioEffect.create` / `EFFECT_TYPE_NULL` / `Equalizer.numberOfEffects` 全是 @hide**

   改用**三个公开工厂类**：`AcousticEchoCanceler.create(id)` /

   ⚠️ 语义边界：`create(sessionId)` 只对**自己拥有的 session** 生效，
